# v0.7.x–v0.8.x implementation plan

These are proposed milestones after the MCU, high-resolution UMP and host-adapter work. Exact patch numbers within each series remain open. The first release gate is a bidirectional wireless capture on the Galaxy S24 Ultra. The layout companion and exchange can share the existing document format without sharing a server.

## v0.7.0 — Network MIDI 2.0 on the local network

**Bench baseline.** The Android 17 Galaxy currently presents a USB MIDI 1.0 byte-stream peripheral to Windows. Cubase 16's MT 4 loopback capture establishes host-side behavior. A network session gives the app ownership of a separate transport over Wi-Fi. UMP consists of 32-bit words. A MIDI 2.0 Channel Voice message occupies **two words**, and a Pitch Bend or CC value can occupy all 32 bits of the second word. Preserve both through the router. [Existing bench evidence](V0.5.x-V0.6.x_IMPLEMENTATION.md) · [MIDI Association UDP transport overview](https://midi.org/network-midi-2-0-udp-overview)

1. **Prove the peer first.** On the target Windows build record MIDI Services version, network transport availability, interface, endpoint names, protocols and groups. Create a Windows Network MIDI 2.0 host. Start with Galaxy as client, direct address and port, then browse through Android NSD for `_midi2._udp`. Implement the reverse role so Windows can discover a Galaxy host. Present a user-controlled invitation/approval flow on a trusted LAN. Microsoft documents approval and the authentication limits of its initial implementation. Record the installed service's behavior. [Windows transport](https://microsoft.github.io/MIDI/kb/network-midi2-transport/) · [Android NSD](https://developer.android.com/develop/connectivity/wifi/use-nsd)
2. **Implement the M2-124-UM session.** Put a bounded datagram codec and session state machine between Dart's RawDatagramSocket and the existing router. Follow the specification's wire order, invitation, acceptance/refusal, sequencing, recovery, keepalive and teardown rules. Keep per-peer sequence windows and retransmit history. Validate command lengths and UMP word counts before enqueueing. Cover duplicate, reordered, missing and wrapped sequences with captured and synthetic packets. Match the peer's datagram limit (Windows documents 1,400 bytes). Reserve capacity for releases and control traffic under continuous fader load. [Network MIDI 2.0 specification](https://midi.org/network-midi-2-0) · [Windows interoperability details](https://microsoft.github.io/MIDI/kb/network-midi2-transport/) · [Dart UDP socket](https://api.dart.dev/dart-io/RawDatagramSocket-class.html)
3. **Integrate one endpoint per session.** Reuse the v0.5.x endpoint, Stream discovery and function-block capabilities. Route complete UMPs by endpoint generation, group and direction. Preserve MT 2 and MT 4 values and existing feedback-loop suppression. Keep USB and LAN independently selectable. On network loss invalidate the old generation, clear touch ownership, and restore a known note/controller state on a fresh session before accepting new gestures. A disconnected peer cannot receive a final Note Off, so exercise recovery at both ends.
4. **Android lifecycle.** Bind discovery and traffic to the selected LAN. Show permission-denied, discovery unavailable, peer declined and session lost separately. Provide manual host/port entry when multicast discovery is unavailable. Check the release manifest for INTERNET. Account for the LAN runtime permission when targeting API 37+ on Android 17, including refusal and revocation. Stop advertising, sockets and timers when the user closes the session. Profile Wi-Fi roaming and screen/background transitions on the physical phone. [Android LAN permissions](https://developer.android.com/privacy-and-security/local-network-permission)
5. **Qualify the wire and the DAW separately.** Capture MT 4 pitch bend `40E00000 80000001` and `40E00000 80000002` in both directions with an exact-value peer. Repeat with CC74 and MT 2 notes. Keep packet words, endpoint identities and negotiated protocol. In Cubase 15 and 16 separately record backend, selected ports, transport buttons, fader touch/write/release and feedback. Log any host conversion. Run a repeated gesture load on USB and Wi-Fi and report same-clock round-trip p50/p95/p99, lost releases, reconnect time and thermal state. Use controlled loss, reordering and Wi-Fi off/on alongside the clean LAN run.
6. **Qualify other desktops individually.** On a supported macOS version select the **Network MIDI 2.0** session in Audio MIDI Setup and repeat exact-word tests. On Linux record a named M2-124 peer, its version and the routing path into the chosen DAW. Keep peer-level and DAW-level results separate. Release the support matrix with measured rows and clearly mark untested combinations. [Apple Audio MIDI Setup](https://support.apple.com/en-mt/guide/audio-midi-setup/ams1012/3.6/mac/27)

## v0.7.x — MPE playing grid and XY/XYZ morph pads

**MPE grid.** Build a polyphonic control alongside AftertouchPad. Persist base note, row/column intervals, playable range, member-channel range and bend range in the layout. For a chromatic fourths layout use one semitone per column and five per row. Define the lower zone with manager channel 1 and up to 15 member channels (2–16). Configure zone size with RPN 6 and synchronize pitch bend sensitivity with the instrument using RPN 0 where supported. Expose manual matching for receivers that require it. This feature can run over the Galaxy's wired MIDI 1.0 route. [MPE specification](https://midi.org/mpe-midi-polyphonic-expression)

1. Map each pointer ID to one member channel and initial note. Initialize bend, CC74 and channel pressure before Note On so a reused channel starts clean. Horizontal travel bends the original note, vertical travel changes timbre, and pressure controls the member's channel pressure. Clamp to configured ranges. Ignore excess touches until lifted when all members are occupied. Protect active member channels from overlapping assignments on the same route.
2. Share the existing note-gate lifecycle across cancel, focus loss, page change, layout replacement and route disconnect. Order Note Off before recycling a member. Coalesce continuous expression per voice while preserving note boundaries. Offer a visible alternative expression control where a finger reports constant pressure. Record the available pressure range for S Pen and finger separately. [Android pointer and pressure data](https://developer.android.com/reference/android/view/MotionEvent)
3. **Morph pads.** Extend the XY control with an explicit morph mode. Store four corner snapshots for XY or two sets of four for XYZ. Interpolate each mapped absolute destination bilinearly or trilinearly in normalized space, then clamp and quantize once to the selected CC or pitch-bend resolution. Reject conflicting duplicate destinations. The first pointer owns XY. Assign Z to calibrated pressure or an explicit second-finger slider, and retain its last value on lift. Keep legacy XY mappings and defaults on import.
4. **Exit evidence.** Replay two simultaneous instances of the same note, crossing fingers, full-zone exhaustion, cancellation during bends and reuse of a released member. Verify independent pitch/timbre/pressure in a named MPE instrument in Cubase. For morphing, test exact corners, edge midpoints, center, both Z layers, mixed-resolution destinations and export/reimport. Measure event rate and frame time during simultaneous morph and MPE use.

## v0.7.x — Haptic detents and accessible feedback

1. Add per-control semantic detents to HybridTouchFader and EndlessEncoderWidget. Pan center is a known midpoint. Unity gain requires a verified host fader curve or explicit layout calibration. A relative V-Pot can tick for each deliberate step. Store opt-in preferences, strength and cue type separately from MIDI values.
2. Detect a user-driven threshold crossing with directional hysteresis and a monotonic minimum interval. Suppress repeats while parked and avoid retriggering from DAW echoes. Queue haptics outside the MIDI dispatch path. On Android query vibrator availability and primitive support, prefer PRIMITIVE_LOW_TICK where supported, and fall back to a supported tick or visual cue. Respect system haptic preferences. [Android vibration primitives](https://developer.android.com/reference/android/os/VibrationEffect.Composition) · [Android haptic guidance](https://developer.android.com/develop/ui/views/haptics/haptics-apis)
3. Provide high-contrast detent marks, textual values and TalkBack labels with adjustable increment/decrement actions. Support reduced motion and optional local audio ticks with independent mute. Announce settled values or deliberate steps so automation does not continuously interrupt speech. Verify touch, keyboard and screen-reader operation, then compare dispatch jitter with cues on/off on the Galaxy. Test with vibration unavailable, audio muted and external DAW automation running. [Flutter accessibility](https://docs.flutter.dev/ui/accessibility-and-internationalization/accessibility)

## v0.8.0 — Phone-hosted browser layout companion

1. **Serve and pair.** On explicit start, bind Dart HttpServer to the selected LAN address, offer port 8080 when available and display the actual URL. Bundle editor assets in the app for offline use. Pair through short-lived credentials and phone confirmation. Validate Host and browser Origin, authenticate each editing connection, limit attempts and message sizes, and expire sessions on stop or network change. Plain HTTP/WebSocket exposes content to the local network. Scope that mode to trusted LANs and disclose that property at pairing. Apply the Android LAN permission handling above. [Dart HTTP server](https://api.dart.dev/dart-io/HttpServer-class.html) · [Dart WebSocket upgrade](https://api.dart.dev/dart-io/WebSocketTransformer-class.html)
2. **Keep the phone authoritative.** Expose a versioned editor protocol with layout ID, document revision, operation ID and acknowledged result. Use the phone's layout model, migrator and storage manager for validation and saving. A bounded preview stream may discard superseded drag positions. Commit final edits reliably and persist only after validation. Deduplicate replayed operations, reject stale revisions, and refresh from the canonical snapshot after reconnect. Handle competing phone edits and browser tabs explicitly.
3. **Deliver the editing workflow.** Support page selection, palette insertion, drag/resize in logical grid coordinates, action assignment, colors, undo/cancel, live preview, export and import. Preserve stable control IDs, unknown-version handling and the existing nine global transport slots. Keep editor previews passive so moving a browser control cannot trigger MIDI or macros. A failed import or interrupted save must preserve the last valid layout.
4. **Exit evidence.** Edit offline from desktop browsers, save, reopen on the phone, then export/reimport and compare layout semantics. Exercise mismatched editor version, interrupted drag, repeated save, stale tab, oversized import, denied pairing and an occupied port. Verify the listener closes on Stop and that editing under load meets the existing performance targets. [Project test guidance](../TESTING.md)

## v0.8.x — Community layout exchange

Use a public, reviewed GitHub repository with a static index and immutable layout downloads. The phone needs read-only HTTPS access. The proposed service uses GitHub's free public hosting within its published limits. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

1. Define an index version and fields for stable template ID, title, author, license, host/version, schema, minimum app version, size, SHA-256 and immutable download location. Start with curated Cubase, REAPER, Live and synth categories. Show the author's tested host version separately from project verification.
2. Accept submissions through pull requests. Validate file limits, schema migrations, permitted assets, attribution, unique IDs and declared hashes before publishing. Publish immutable files before replacing the index. Pin the catalog origin in the app and restrict downloads to approved locations. A digest detects artifact mismatch. Repository review controls who can change the index.
3. Cache the last valid index using HTTP validators. Back off on rate limits and retain downloaded layouts offline. Verify size, hash and schema before showing a passive preview of mappings and macros. Import as a new local document through LayoutStorageManager so an update preserves the user's customized copy. Test stale cache, withdrawn template, digest mismatch, unsupported schema, offline import and interrupted download.

## v0.8.x — Foldable, DeX and multi-window performance

1. Base layout on available window bounds, hinge/display features and per-pane minimum usable width. Start with a single viewport. Offer dual-pane when both surfaces fit, including on a resized DeX window. Keep touch targets clear of a separating hinge. Preserve layout grid coordinates and per-pane scale/pan when switching modes. [Android foldable guidance](https://developer.android.com/develop/adaptive-apps/guides/foldables/learn-about-foldables) · [Samsung DeX optimization](https://developer.samsung.com/samsung-dex/modify-optimizing.html)
2. Pin an MCU mixer page on one side and choose an XY, macro or transport page on the other. Persist logical page IDs and restore gracefully when a page disappears. Both panes share one MIDI service, router, feedback subscription per address and the existing global 3×3 transport. Track gesture ownership per pointer/control and release active gates before disposing or reassigning a pane.
3. Support keyboard focus traversal, mouse drag/wheel and touch independently. On resize, fold/unfold, display transfer or focus loss, preserve saved layout and end invalid gestures once. Verify single and dual panes with a foldable emulator, then verify real MIDI and mouse/keyboard operation on the Galaxy with an external DeX display. Record unavailable hardware separately. Exercise background/restore, rapid resizing and simultaneous host feedback. Exit with evidence of accurate hit targets, stable frame times, one outgoing event per action and no held notes.

## Delivery order

Land protocol fixtures before network UI, voice allocation before the MPE grid, interpolation before morph gestures, and semantic detent detection before device cues. Deliver browser pairing and revision handling before drag editing. Reuse document validation for the catalog. Qualify adaptive panes against both expressive controls and the existing MCU surface. Keep each review unit scoped to its behavior and use the repository's existing commit conventions.
