### Run D Findings

- **Full 32-bit storage & playback:** Cubase 16 MIDI tracks record and replay `MT=0x4` CC 74 and Pitch Bend without 7-bit or 14-bit quantization (`0x80000001` vs. `0x80000002` remained distinct).
- **Continuous curve interpolation:** Because Cubase defaults MIDI CC/Pitch Bend lanes to continuous ramp interpolation between nodes, `02-playback-capture.csv` (`186` rows) contained dense interpolated 32-bit `MT=0x4` ramps (~50 ms cadence for CC 74, ~6 ms cadence for Pitch Bend) between recorded points, plus intermediate `0x80000000` values near the center dwell and stop/rewind chase emissions.
- **Record auto-monitor echo:** Live Thru returned 8/8 injected `MT=0x4` packets bit-for-bit on Loopback A while recording.

## 6. Cubase 15 vs. Cubase 16 MCU Wire-Protocol Comparison & Design Impact

| MCU Signal | Cubase 15 (`WinRT`, `MT=0x2`) | Cubase 16 (`Windows MIDI Services`, `MT=0x4`/`MT=0x3`) | Phase 2/v0.5.x Requirement |
| --- | --- | --- | --- |
| **LED On** | `0x2090nn7F` (Note On vel `127`) | `0x4090nn00 0xFFFF0000` (16-bit vel `0xFFFF`) | Decode Note On `MT=0x2` vel7 and `MT=0x4` `velocity16 >>> 9`. |
| **LED Off** | `0x2090nn00` (**Note On vel `0`**) | `0x4080nn00 0x80000000` (**explicit MIDI 2.0 Note Off**) | Treat **both** Note On (`vel == 0`) and Note Off (`0x80`, any release velocity) as LED OFF across `MT=0x2` and `MT=0x4`. |
| **Fader Touch Release (Host Rx)** | Accepts both `0x20806800` and `0x20906800` | Accepts both `0x20806800` and `0x20906800` | Retain baseline `0x80 nn 00` release on controller egress (with `MT=0x2`/byte parity). |
| **Fader Feedback (`E0..E8`)** | `0x20Enllmm` (14-bit) | `0x40En0000 <u32>` (bit-repeated lower 18 bits above `0x80000000`, zeroed below) | Extract top 14 bits (`Word1 >>> 18`) for MCU faders without assuming lower 18 bits are zero. |
| **V-Pot Rings (`CC 30..37`)** | `0x20B03s vv` | `0x40B03s00 <u32>` (bit-repeated lower 25 bits, e.g., `0xACB2CB2C` → `0x56`) | Extract top 7 bits (`Word1 >>> 25`) before decoding mode/value bits `6..0`. |
| **Timecode Digits (`CC 40..4B`, Ch 16)** | `0x20BF4d vv` | `0x40BF4d00 <u32>` | Extract top 7 bits (`Word1 >>> 25`) across `MT=0x2` and `MT=0x4`. |
| **LCD Scribble Strip (`00 00 66 14 12`)** | `MT=0x3` `DataMessage64` SysEx7 (`0x30160000 0x661412..`) | `MT=0x3` `DataMessage64` SysEx7 (`0x30160000 0x661412..`) | Unified `MT=0x3` SysEx7 + byte-stream `F0..F7` reassembly handles both hosts identically (v0.5.1/v0.5.2). |

## 8. Phase 3 MCU V-Pot Pan Parity & Indicator Design Findings

- **Why `CC 0x30..0x37` Cannot Provide 1-Unit Pan Parity:** Unlike MCU faders (which exchange full 14-bit Pitch Bend `0..16383` values enabling accurate dB calculation such as `-20.0` or `+6.02`), Mackie Control never transmits an absolute numeric pan value over CC. `CC 0x30..0x37` bits `3..0` only encode an **11-LED ring bucket index (`1..11`)** plus center bit `6` (`0x40`). Because Cubase's 201-step pan range (`L`, `L99..L1`, `C`, `R1..R99`, `R`) maps onto 11 buckets, `v0.5.0` displays quantized bucket readouts (`L`, `L80..L20`, `C`, `R20..R80`, `R`).
- **Why Local Tick Counting Is Avoided:** Counting local `CC 0x10..0x17` relative steps (`-100..+100`) was deliberately rejected because it drifts from Cubase on project loads, undo, automation playback, host mouse edits, encoder acceleration, and non-linear/stereo panner modes—since Cubase only echoes coarse 11-bucket ring updates back over CC.
- **Path to True 1:1 Pan Parity (`v0.5.1 / v0.5.2`):** Exact `L / L99..L1 / C / R1..R99 / R` parity requires decoding Cubase's MCU SysEx LCD scribble-strip messages (`F0 00 00 66 14 12 <offset> <text> F7`), delivered identically as 64-bit UMP `MT=0x3` `DataMessage64` SysEx7 packets on both Cubase 15 (WinRT) and Cubase 16 (Windows MIDI Services).
- **Cubase V-Pot Push & Indicator Layout (`v0.5.0`):** In Cubase's Mackie Control mapping, tapping a V-Pot (`Note 0x20..0x27`) toggles Track **Monitor** without sending a MIDI Monitor LED reply back to the surface. Accordingly, `EndlessEncoderWidget` splits the indicators for clarity: Monitor ON/OFF fills the knob circle (`#FFB300` amber fill with `#1A1400` dark text when active), while the outer 270° LED ring (`#64B5F6` bidirectional arc from 12 o'clock) renders Pan position. MCU V-Pot drag sensitivity is tuned to `6.0` logical px/step (vs. `1.5` on generic encoders) for fine 1-unit panning steps on touchscreens.
